# Any-Family 架构设计

> 一页地图：系统怎么分层、数据怎么流、每块跑在哪。详细技术选型见 [RESEARCH.md](RESEARCH.md)。

## 1. 部署拓扑

```
            家庭内网                                       公网 / 远端
┌─────────────────────────────────┐              ┌──────────────────────┐
│  本地服务器（Agent 本体）           │              │  父母端 App           │
│                                 │              │  iOS / Android (RN)   │
│  ┌───────────────────────────┐  │   WebRTC     │   · 实时看宠物         │
│  │ Agent 中枢 (Python)        │  │◀────信令/媒体─▶│   · 与 agent 对话     │
│  │  感知→记忆→决策→表达         │  │   + 推送      │   · 远程逗玩          │
│  └───────────┬───────────────┘  │              │   · 看习惯/健康报告    │
│              │                  │              └──────────────────────┘
│  ┌───────────┴───────────────┐  │
│  │ LiveKit server (自托管)     │  │   阶段二：
│  └───────────────────────────┘  │   ┌────────────────────┐
│                                 │   │ IP 摄像头 (RTSP)     │
│  数据源:                         │◀──│ → go2rtc + FFmpeg    │
│   阶段一 本地视频/图片/音频文件     │   └────────────────────┘
└─────────────────────────────────┘
```

- Agent 本体与所有感知模型、记忆都在**家庭本地服务器**，隐私数据不出内网。
- 父母端经 **LiveKit（WebRTC）** 跨网访问；提醒经 **APNs/FCM 推送**。
- 对话大模型可选本地或线上 API（可配置）。

## 2. Agent 中枢：能动闭环

这是一个**能动 Agent**，不是被动监控：感知 → 记忆 → 规划 → 执行器 → 反馈，围绕事件总线解耦。

```
  ┌──────── 事件总线 (perception.* / decision.* / action.* / health.*) ───────────────┐
  └──▲──────────────▲──────────────▲────────────────▲──────────────────▲──────────────┘
     │ perception.* │ (读写)        │ (读)            │ action.request   │ action.result
┌────┴──────┐  ┌────┴──────┐  ┌─────┴──────┐   ┌──────┴───────┐   ┌──────┴───────┐
│ 感知 Perc. │  │ 记忆 Memory│  │ 规划 Plan   │   │ 执行器 Device │   │ (反馈回记忆)  │
│ 检测/VLM   │  │ 时间线/画像│  │ 解读+规划    │──▶│ speak/camera │──▶│ 结果→解读校准 │
│ 姿态/音频   │  │ 异常基线   │  │ 对话/主动    │   │ play/feed    │   │              │
└───────────┘  └───────────┘  └────────────┘   └──────────────┘   └──────────────┘
         资源协调 ResourceCoordinator（VLM/姿态模型 显存互斥、按需加载）
```

> 已有可运行 MVP 骨架（`server/`）：StubDetector 感知 → 规则 Interpreter/Planner → MockCompanionDevice 执行，
> 全链路 `uv run python scripts/smoke.py` 可跑通。

### 2.1 感知层 Perception
- 常驻：YOLO 检测（宠物在不在/位置/运动）→ 事件。
- 触发：VLM 关键帧语义理解、姿态关键点、行为分类、宠物叫声/人声音频。
- 产出统一的结构化 `perception.*` 事件（时间、类型、置信度、关联媒体片段）。

### 2.2 记忆层 Memory
- 短期：当日事件时间线。
- 长期：作息画像（活跃时段/饮食/焦虑触发）、异常基线、关系与偏好。
- 技术：向量检索（语义召回）+ 结构化画像，本地存储。

### 2.3 规划/决策层 Planning（能动 Agent 的大脑）
不是只会报告，而是**理解需求 → 规划 → 调用能力执行 → 看反馈**（业界具身 Agent 范式：
大脑规划、小脑控制，见 RESEARCH 第 7 章）：
- 解读 Interpreter：把感知硬信号（叫声 VA + 活动 + 历史/画像）融合成带证据的"软解读"。
- 规划 Planner：按解读 + 宠物偏好 + 可用设备能力，决定是否行动、调哪个能力（规则版，可接 LLM）。
- 被动对话：父母提问 → 组装上下文 → LLM 回答。
- 主动陪伴：宠物焦虑/孤单时自主安抚（放音/逗玩）。
- 健康预警：行为偏离画像基线 → 提醒父母（含趋势证据，防误报）。

### 2.4 执行器/设备层 Actuator（小脑：驱动硬件）
把宠物陪伴硬件（你已有的机器人：语音/摄像头/逗玩/投食）抽象成 **Device + 能力工具**：
- `Capability`：speak / camera / play / feed，即 Agent 可调用的工具。
- `Device` 接口：接新硬件只实现它（在 `execute()` 里发 BLE/REST/MQTT 指令），上层不改。
- `ActuatorRegistry`：订阅 `action.request` → 路由到支持该能力的在线设备执行 → 回发 `action.result`。
- 安全约束：如投食每日上限，避免 Agent 失控。
- 对父母：实时流、对话回复、推送提醒、习惯/健康报告。

## 3. 资源协调

本地服务器显存有限，`ResourceCoordinator` 统一管理 VLM / 姿态模型的加载：
- 检测器轻量常驻；重模型按事件触发、用完释放；多重模型互斥，避免 OOM。

## 4. 数据源抽象

定义统一 `MediaSource` 接口，让"本地文件"与"摄像头实时流"对感知层透明：
- 阶段一：`FileMediaSource`（遍历本地视频/图片/音频）。
- 阶段二：`StreamMediaSource`（go2rtc 提供低清流给感知 + 高清流给直播）。

## 5. 模块映射（规划）

| 目录 | 职责 |
| --- | --- |
| `server/agent/` | 中枢四层 + 事件总线 + 资源协调 |
| `server/perception/` | 检测 / VLM / 姿态 / 音频 分析器 |
| `server/memory/` | 时间线 / 画像 / 向量检索 |
| `server/media/` | MediaSource 抽象 + go2rtc/FFmpeg 适配 |
| `server/realtime/` | LiveKit 接入（agent worker / token / 房间） |
| `mobile/` | 父母端 React Native App |
| `shared/` | 跨端协议与类型（事件/消息契约） |
