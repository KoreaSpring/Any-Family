# Any-Family 父母端产品设计

> 本文定义父母端 App（iOS / Android）的功能形态与实现方案。技术选型依据见 [RESEARCH.md](RESEARCH.md)，
> 系统架构见 [ARCHITECTURE.md](ARCHITECTURE.md)。
>
> **一句话产品定位**：不是一个宠物监控摄像头 App，而是一个"越用越懂你家宝贝的翻译官 + 健康管家"。

---

## 0. 诚实边界（设计前必须对齐的三条红线）

做这个产品前，有三件事必须对团队和用户都说清楚，否则会做成"看起来酷但不可信"的玩具：

1. **不做"宠物翻译机"**：动物没有人类词汇，不能逐词翻译。我们做的是**情绪/状态/需求的解读**，
   并始终给出"依据"和"置信度"。参见 RESEARCH.md 第 5 章。
2. **健康功能是"提示去检查"，不是"诊断"**：AI 的价值是**可重复、可追踪的客观测量 + 异常提示**，
   最终诊断必须由兽医做。所有健康提示都要带免责声明与"建议就医"引导。参见 RESEARCH.md 关于步态分析。
3. **"看到我"不是让宠物听懂一句新话**：科学证据表明狗对**熟悉指令词 + 熟悉的声音**响应最好
   （直接人声≈100%，扬声器回放人声≈70%，电子按钮音≈30%）。所以这个功能的正确形态是
   **远程用它熟悉的话/主人的声音安抚与下达已训练过的指令**，而不是生成"动物语"。参见 RESEARCH.md 第 5 章。

> 这三条不是泼冷水，而是产品可信度的根基——我们用"诚实但有用"赢得信任，而不是用"神奇但不准"消耗信任。

## 1. 整体信息架构

```
首次启动
  └─ 引导录入流程（Onboarding）
       拍照/录视频 → 品种确认 → 基础信息 → 习惯/喜好/猫粮/作息 → 完成
                                                        │
                                                        ▼
首页（Home）
  ┌──────────────────────────────────────────┐
  │  3D 宠物形态图（360° 可旋转）                 │
  │   · agent 学习后生成的这只宠物的 3D 形象       │
  │   · 叠加健康标注（类"穴位图"）：异常部位高亮     │
  │   · 点击标注 → 该部位的观察依据 + 建议检查       │
  ├──────────────────────────────────────────┤
  │  三个入口：                                  │
  │   [🔍 了解宠物]  [👂 听懂我]  [💬 看到我]        │
  └──────────────────────────────────────────┘
       │              │              │
   汇总信息页      音频→文字解读     文字→熟悉语音回放
```

## 2. 引导录入流程（Onboarding）

目标：**低摩擦地拿到"冷启动个性化"所需的信息**（品种先验 + 个体基础），同时拿到 3D 重建的素材。

### 2.1 步骤设计

| 步 | 界面 | 采集内容 | 技术动作 |
| --- | --- | --- | --- |
| 1 | 拍照 / 录一段视频 | 1 张清晰正面照（必填）+ 可选 10–20s 走动视频 | 照片用于品种识别 + 3D 重建；走动视频用于更好的 3D 体型 + 步态基线 |
| 2 | 品种确认 | 展示模型识别的 Top-3 候选品种，用户点选/手动改 | 调品种识别模型（Stanford Dogs/Oxford Pet 微调），拿到品种 → 加载品种先验 |
| 3 | 基础信息 | 名字、物种(猫/狗)、年龄、性别、是否绝育、体重 | 结构化入库；年龄/绝育影响健康基线 |
| 4 | 习惯与作息 | 作息时间（睡/活跃时段）、喂食时间与次数 | 作为"作息画像"的初始先验，后续被真实观测校准 |
| 5 | 喜好与饮食 | 爱吃的/猫粮狗粮品牌、喜欢的玩具/互动、怕什么 | 进个体画像；"看到我"的指令词、安抚方式来源 |
| 6 | 完成 | 展示"正在为 XX 生成专属形象…" | 触发后台 3D 重建 + 初始化画像，完成后进首页 |

### 2.2 设计要点

- **可跳过、可补填**：除品种和照片外都可跳过，首页提供"完善资料"入口持续补全。信息越全，解读越准，
  用进度条/完成度激励补填。
- **录入即建档**：录入完成即创建该宠物的 `PetProfile`（见第 7 节数据结构），品种先验此刻注入。
- **多宠物**：支持添加多只，每只独立档案与 3D 形象。

## 3. 首页：3D 宠物健康形态图

这是产品的"门面"，也是技术含量最高的一块。拆成**3D 形象**和**健康标注**两件事。

### 3.1 3D 形象生成（可行，有开源基础）

**技术路径**：参数化动物模型 + 单图/视频重建。

- **底模**：**SMAL**（Skinned Multi-Animal Linear model，动物界的"SMPL"），用少量形状/姿态参数描述四足动物体型与姿势。
- **从用户照片/视频重建**：
  - 单图路径：**BARC**（利用品种信息回归 3D 狗体型，正好契合我们已拿到品种）、**SMAL-pets**（单图生成可编辑 avatar）、**CORGI**（野外单图 3D 狗重建）。
  - 视频路径（更高质量、可动画）：**AnimalAvatar**（Facebook/ECCV 2024，有开源代码，从随手视频重建可动画 3D 动物）。
- **渲染与交互**：3D 资产（mesh + 纹理）在手机端用引擎渲染，支持 **360° 旋转、缩放**。RN 侧可用
  `react-native-filament` / `three.js`(via GL) / 原生 SceneKit·Filament 封装。
- **分阶段**：
  - **MVP**：先用"品种对应的通用 3D 底模 + 用户照片贴图近似"，快速出可旋转形象（不追求高保真个体化）。
  - **进阶**：用用户视频跑 AnimalAvatar 出个体化可动画形象，agent 还能驱动它复现"今天它的典型姿态"。

> 重建是**本地服务器**上的离线任务（算力大），生成好的轻量 3D 资产下发给手机渲染。参见 RESEARCH.md 关于 3D 重建来源。

### 3.2 健康标注（"穴位图"式异常提示）

**定位**：在 3D 形象上，像穴位图一样把"观察到可能异常的部位/系统"高亮，点击看依据与建议。
**这是提示，不是诊断**（见第 0 节红线）。

**异常信号从哪来**（都来自已有的感知链路，映射到身体部位/系统）：

| 身体部位/系统 | 异常信号来源 | 举例 |
| --- | --- | --- |
| 四肢 / 步态 | 姿态关键点 → 肢体对称性、步态参数异常（跛行检测） | "右后腿着地时间偏短，疑似不适，建议观察/就医" |
| 皮肤 / 体表 | 事件触发 VLM + 行为（频繁抓挠/舔同一部位） | "近 3 天频繁舔舐左前爪" |
| 消化 / 饮食 | 食盆 zone 事件 + 行为（进食量/频率偏离基线） | "今日进食次数低于往常" |
| 情绪 / 精神 | VA 情绪趋势 + 活跃度（持续低落/异常高唤醒） | "连续两天活跃度明显下降" |
| 呼吸 / 其他 | 音频事件（异常喘息/咳嗽声）+ 姿态 | "夜间出现疑似咳嗽声" |

**交互**：
- 正常部位不标注，异常部位按严重度用颜色高亮（黄=留意，红=建议尽快就医）。
- 点击 → 展开"观察依据（证据链：哪些事件/趋势支撑）+ 置信度 + 建议 + 一键记录/预约兽医"。
- 底部固定免责声明：本提示不构成诊断，请以兽医检查为准。

**实现方式**：维护一个"身体部位 ↔ 异常信号"的映射表 + 规则/阈值引擎（偏离个体基线触发），
由 agent 决策层产出 `health.alert` 事件，前端在 3D mesh 对应骨骼/区域上做高亮锚点。

## 4. 入口一：🔍 了解宠物（汇总信息）

点进来看到的是 agent 对这只宠物学习后的**汇总解读**，而不是原始监控流水。

**内容分区**：

1. **今日概览**：一句话总结（"今天 Lucky 过得不错，上午玩得很嗨，下午大部分时间在窝里睡觉"）+ 关键指标卡片（活跃时长、进食、睡眠、情绪基调）。
2. **时间线**：按时间排列的事件卡（在吃/睡/玩/闹/异常），每张卡带缩略图/短片段 + 一句解读 + 情绪标签。
3. **习惯画像**：学习出来的作息规律（活跃时段热力图）、饮食规律、黏人/焦虑时段、"它的小癖好"。
4. **品种 vs 它**：展示"品种普遍倾向"与"你家这只的实际表现"对比（护城河体验点，见 RESEARCH.md 第 6 章）。
5. **健康趋势**：体重、活跃度、情绪、异常事件的时间趋势图，与 3D 形态图的健康标注联动。

**数据来源**：记忆层（时间线 + 画像 + 异常基线）。前端只做展示与下钻，解读在服务端由 agent 生成。

**交互**：支持提问式下钻——顶部有对话框"问问 Lucky 今天怎么样"，复用对话大脑，answer 带证据链接回时间线。

## 5. 入口二：👂 听懂我（宠物音频 → 文字解读）

**功能**：实时把宠物的声音（叫声/呜咽/喘息等）解析成**文字化的情绪与需求解读**。

**再次强调边界**：不是逐词翻译，是"状态 + 可能需求 + 置信度 + 依据"（见第 0 节、RESEARCH.md 第 5 章）。

### 5.1 两种模式

- **实时模式**：父母在 App 里开着，本地服务器把麦克风/摄像头音轨实时送解析，App 滚动显示解读。
  例："（刚刚）短促高频吠叫 ×3，高唤醒度 → 可能在警戒门外的动静"。
- **回看模式**：对时间线里某段叫声点击"解读这段"，给出同样结构的结果。

### 5.2 技术链路

```
音频流 → VAD 切分出"宠物发声片段"
      → 叫声情绪模型（VA 效价/唤醒 + 叫声类型分类）
      → 同时取同时刻视觉上下文（在哪/在干嘛/表情）
      → 多模态融合（late-fusion）
      → LLM 结合品种先验 + 个体画像 → 生成一句解读 + 置信度 + 依据
      → App 展示（并写入记忆）
```

- 关键：**带上视觉上下文和历史**。同样的叫声，"在门口 + 傍晚 + 你平时这时回家"→"等你回家"；
  "在食盆边 + 接近饭点"→"饿了"。这正是比"纯音频分类"更懂的地方。
- 展示解读时给**置信度**与**依据**，不确定就说"不太确定，可能是…"，宁可谦虚不要瞎翻译。

## 6. 入口三：💬 看到我（文字 → 它熟悉的语音回放）

**功能**：父母输入文字，远程通过家里的扬声器"说给"宠物听，用它熟悉的方式安抚或下指令。

### 6.1 正确的产品形态（基于科学证据）

科学证据（UCSD 2025）：狗对**熟悉指令词 + 熟悉声音**响应最好。所以这个功能不是"造动物语"，而是：

- **指令词模式**：从宠物已训练过的指令里选（坐下/过来/等待/吃饭了…），系统用**主人克隆的声音**
  （或主人预录的声音）通过家里扬声器播放。用熟悉的词 + 熟悉的声音，响应率最高。
- **安抚模式**：输入任意安抚的话 → 用主人声音念出来播放（宠物未必懂词义，但熟悉的声音本身能安抚）。
- **声音库**：引导阶段/日常可录制主人常说的话，建立"熟悉声音库"，效果优于 TTS 合成的陌生声音。

### 6.2 技术链路

```
父母输入文字 / 选指令
   → 是已训练指令？── 是 → 取主人声音库中该指令录音（或声音克隆 TTS 念指令词）
                   └ 否 → 主人声音克隆 TTS 念出这句话（安抚为主）
   → 下发到本地服务器 → 家中扬声器播放
   → （可选）同步看宠物反应（摄像头）→ 记录"指令-反应"用于效果学习
```

- **声音克隆**：用主人少量语音样本克隆音色（本地或可控的 TTS），避免陌生电子音（响应率最低那一档）。
- **闭环学习**：记录"下了什么指令 / 宠物有没有反应"，长期学习"对你家这只哪些话最管用"，反哺解读与建议。
- **诚实提示**：UI 明确告知"宠物主要靠熟悉的声音和训练过的词反应，陌生长句它可能听不懂"。

## 7. 关键数据结构（跨端契约，详见 shared/）

```jsonc
// PetProfile —— 录入时创建，持续被观测校准
{
  "id": "pet_xxx",
  "name": "Lucky",
  "species": "dog",            // dog | cat
  "breed": "golden_retriever", // 品种识别 + 用户确认
  "age": 3, "sex": "male", "neutered": true, "weight_kg": 28,
  "habits": { "active_hours": [...], "feed_times": [...] },
  "preferences": { "food": [...], "toys": [...], "fears": [...] },
  "trained_commands": ["sit", "come", "wait"],   // 供"看到我"
  "voice_profile_id": "voice_xxx",               // 主人熟悉声音库
  "breed_prior": { /* 品种先验快照 */ },
  "individual_profile": { /* 个体画像，随观测增长 */ },
  "prior_weight": 0.8          // 品种先验 vs 个体观测的动态权重，随数据下降
}

// Interpretation —— "听懂我"/解读的统一结构（带证据与置信度）
{
  "ts": 1730000000, "pet_id": "pet_xxx",
  "state": { "valence": -0.3, "arousal": 0.7 },   // VA 情绪坐标
  "label": "可能在焦虑地等你回家",
  "confidence": 0.62,
  "evidence": ["门口徘徊 5min", "高唤醒度吠叫 x4", "历史:你出门时常如此"],
  "modalities": ["audio", "video", "memory"]
}

// HealthAlert —— 3D 形态图标注来源
{
  "ts": 1730000000, "pet_id": "pet_xxx",
  "region": "right_hind_leg", "severity": "warn",  // warn | urgent
  "finding": "右后腿着地时间偏短",
  "evidence": ["步态对称性偏离基线 3 天"],
  "advice": "建议观察，持续则就医",
  "disclaimer": "本提示不构成诊断"
}
```

## 9. 风险与注意（产品侧）

- **期望管理**：首页 3D 和"听懂/看到"极易被用户当成"魔法"，务必在 UI 里用"解读/提示/置信度"措辞，避免过度承诺。
- **健康合规**：健康相关一律"提示 + 免责 + 引导就医"，不出现诊断性结论。
- **隐私**：家庭音视频默认本地处理；主人声音样本等生物特征数据需显式授权、本地存储、可删除。
- **冷启动体验**：MVP 阶段解读偏泛属正常，用"正在学习 XX，解读会越来越准"引导用户持续用、持续补资料。
- **猫**：猫的解读与品种先验较弱，先做狗，猫标注"实验性"。
